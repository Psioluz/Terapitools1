⚠️ Limitaciones conocidas de este panel
Este panel usa la misma anon key REST que las demás apps - no tiene acceso a la Management API de Supabase. Eso significa: el uso de almacenamiento mostrado abajo es una aproximación (suma de tamaños de archivos listados, no la cuota real del proyecto); "Backups" genera un export JSON descargable, no un backup nativo de Postgres; y el log de errores solo recibe lo que cada app reporta activamente (no es una auditoría completa).
Vista de solo lectura para revisar qué se ha llenado en Supabase, sede por sede. Para editar usa "Tablas de Supabase".
Las filas con cambios sin guardar se resaltan en amarillo. Los campos con 🔒 (id, fechas de creación) no se pueden editar. El filtro de Sede se ignora en tablas que no tienen columna "sede" (ej. Sedes). Si pegas un ID en "Buscar por ID", se ignoran el filtro de sede y el límite y se busca esa fila exacta en la tabla seleccionada.

🧼 Vaciar Paciente
Borra TODO lo registrado de un paciente (sesiones, paquetes, terapias del paquete, pagos y precios exclusivos) - la fila del paciente en la tabla "pacientes" NUNCA se toca. Úsalo para limpiar datos de prueba o corregir un registro mal hecho desde cero.
🧮 Recalcular Saldo
El saldo de un paciente (y de sus paquetes) es un total que el sistema va sumando/restando con cada sesión o pago - si algo se corrigió por fuera de ese flujo normal (ej. un ajuste manual en la base de datos), puede quedar desincronizado con la realidad. Esta herramienta vuelve a sumar desde cero, a partir de las sesiones y pagos reales del paciente, y corrige cualquier desfase.
